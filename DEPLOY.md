# Развёртывание в Docker

## Требования к серверу

- Docker 20.10+ и docker compose v2 (`docker compose version`).
- 1 ядро, 1 ГБ RAM — для команды до 10 человек хватает.
- Свободный порт **8021** (или поправьте в `docker-compose.yml`).
- Доступ сотрудников только из локальной сети / VPN.

## Первый запуск

1. Скопировать на сервер папку `sverka-web` целиком
   (через WinSCP/scp/rsync).
2. На сервере выполнить:

   ```bash
   cd sverka-web
   docker compose up -d --build
   ```

3. Проверить, что контейнер живой:

   ```bash
   docker compose ps
   curl -I http://localhost:8021/healthz
   ```

4. Открыть в браузере: `http://<IP-сервера>:8021`.

Файлы сверок сохраняются в Docker-том `sverka-data`. При перезапуске
контейнера ссылки на скачивание продолжают работать.

## Обновление кода

```bash
cd sverka-web
# залить новые файлы (app.py, core.py, templates, static)
docker compose up -d --build
```

`up -d --build` пересоберёт образ и заменит контейнер без простоя данных.

## Логи и диагностика

```bash
docker compose logs -f          # живой лог
docker compose logs --tail=200  # последние строки
docker compose restart           # перезапуск
docker compose down              # остановить и удалить контейнер (том сохранится)
```

## Чистка старых сверок

Каждая загрузка создаёт папку в томе. Если накопится много —
запустить ручную чистку (удаляет всё старше 30 дней):

```bash
docker compose exec sverka find /data -mindepth 1 -maxdepth 1 \
    -type d -mtime +30 -exec rm -rf {} +
```

Можно положить эту команду в cron на хосте.

## Порт за реверс-прокси

Если у вас уже стоит общий Nginx для внутренних сервисов — пробросьте
на `127.0.0.1:8021` и закройте порт 8021 снаружи (`ports: "127.0.0.1:8021:8021"`
в `docker-compose.yml`).

## Что внутри контейнера

- **Gunicorn**, 2 воркера, таймаут запроса 10 минут (крупные файлы парсятся ~1 мин).
- **Лимит загрузки** одного файла — 100 МБ (`MAX_CONTENT_LENGTH` в `app.py`).
- **Рабочая папка** `/data` (Docker-том). Управляется через переменную
  окружения `SVERKA_WORK_DIR`.
- **Пользователь** в контейнере — непривилегированный `sverka` (uid 1000).
- **Healthcheck**: `GET /healthz` каждые 30 секунд.

## Безопасность для внутренней сети

Авторизация не настроена, потому что доступ ограничен LAN/VPN.
Если в будущем потребуется открыть наружу — поставьте Nginx с basic auth
перед контейнером и HTTPS через certbot.
